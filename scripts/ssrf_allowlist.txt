# SSRF fetch-site allowlist (issue #2131) — pre-existing debt, shrink only.
#
# scripts/check_ssrf.py flags every `client.get(url)` / `reqwest::get(url)`
# whose URL is a variable and whose enclosing function does not call
# botsecurity_core::validation::fetch_user_url. An entry here says the site
# is NOT caller-supplied: the host comes from a constant in the module or
# from server-side configuration (Vault/env), so a request cannot redirect
# it at the metadata endpoint or an internal service.
#
# Format: <repo-relative path> # <why this fetch cannot reach an
# attacker-chosen host>. Entries that no longer suppress a violation are a
# gate failure, so fixing a file forces its line to be deleted.
