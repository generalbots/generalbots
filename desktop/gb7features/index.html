Feature Set — Chat + Drive

The commercial feature case for GB7: a private, file-aware assistant for the desktop. Each card states the customer problem and the outcome delivered, and the availability table shows what a customer can use today in the current edition.

14 features 12 available 2 partially available

Chat experience

Everything the user does in the conversation: asking, searching, generating, attaching and remembering.

GB6-08Available

Web search with citations

Users expect current answers; unsourced answers feel less trustworthy than the web itself.

Outcome: Answers that use the web carry clickable source chips taken from the pages actually read.

Sources travel with the answer and are presented as references, so a claim can always be traced back.

GB6-09Available

Artifacts and generated documents

Long-form output is the top “wow” moment for assistants; plain chat text undersells the product.

Outcome: A long answer, report or page can be opened as a document, previewed, saved to Drive and opened later.

Works for prose reports, structured markdown, HTML pages and code — not only for code blocks.

GB6-10Available

Model picker with plain-language trade-offs

Power users cannot tune speed, quality or cost; there is no visible control over the assistant.

Outcome: The user switches between Fast, Balanced and Quality, each labelled with its trade-off, and the request is routed to the model configured for that tier.

Unconfigured tiers fall back to the default model, so the switch never breaks a conversation.

GB6-15Available

Attachments in chat

Users expect to drag a file into the conversation instead of uploading first.

Outcome: Drag or attach a file in chat; the assistant reads its content and answers from it in the same turn.

Text, CSV, JSON, markdown and office/PDF documents are extracted into the conversation; media is reported honestly as unreadable.

GB6-16Available

Memory across conversations

Repeating context every session makes the assistant feel dumb.

Outcome: “Remember …” stores the preference on the server, every later session starts with it, and settings show what is remembered.

Memory is scoped to the user and the bot, and can be reviewed or removed in Settings.

GB6-31Available

Chat opens automatically on launch

The user should land on the main job, not a launcher.

Outcome: The desktop opens straight into a ready conversation.

Drive and files

Finding, previewing, sharing and recovering the user’s files.

GB6-11Available

Search across all files

Folder browsing alone does not scale; finding a file is table stakes for a file space.

Outcome: One search box covers every folder the user can open and matches both file names and file content.

Nested folders are searched, result sizes are shown, and the search never reaches another tenant’s files.

GB6-12Available

File previews for common formats

Users must confirm they picked the right file before acting on it.

Outcome: PDF, images, text, CSV and office documents open in a preview instead of being downloaded.

Office documents are converted for preview, so the customer never leaves the app to check a file.

GB6-13Available

Share and export a file

Files are only useful if they can leave the app when the user needs them to.

Outcome: Create a link with a chosen expiry, send it to a recipient, or export a folder as a single archive.

Links are revocable and expire automatically; exports produce one downloadable file instead of many.

GB6-14Available

Version history and trash

Mistakes must be recoverable; otherwise users are afraid to edit.

Outcome: Deleting moves the file to Trash with 30-day retention and one-click restore; overwriting keeps the previous versions.

Both the Trash and the version list are reachable from the Drive window, not hidden in a developer screen.

Automation and integrations

Letting the assistant work with the user’s tools, not only describe them.

GB6-18Partially available

Connectors with consent

Move from “assistant that reads files” to “assistant that works with your tools”.

Outcome: A user connects a cloud account, sees exactly which permissions are requested and granted, and can disconnect in one click.

The consent and disconnect experience is in place; connecting a live Google or Microsoft account still requires the provider credentials to be configured for the deployment.

GB6-19Available

Computer use — browser actions

Lets the assistant do work on the web instead of only describing it.

Outcome: The assistant proposes opening a page, the user approves the action, and the result appears in the conversation.

Nothing runs silently: every browser action starts from an explicit consent card.

GB6-20Available

Computer use — terminal actions

Power users want scripts and local tools driven by the assistant.

Outcome: A command runs only after explicit approval, and every decision is recorded in an audit trail.

Approval, exit status and output are kept together, so an administrator can reconstruct what ran and why.

Product and trust

Controls that make the assistant usable and accountable every day.

GB6-25Partially available

Usage and cost transparency

Users need to understand what each model costs before trusting the tool daily.

Outcome: A usage view lists messages and tokens per day and per model; when a price list is configured it also shows the cost.

Without a price list the panel says that cost is unavailable instead of showing a made-up number.
