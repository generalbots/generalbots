2018 — The founding bet: bots as packages, not code

ce73db22f · 2018-04-21 · "Initial import."

The very first README states the thesis plainly, and it is a thesis that took eight years to fulfil:

*"General Bots is a packaged based chat bot server focused in **convention over
configuration and codeless approaches** … everyone can create bots copying and pasting some
files and using their favorite tools like Excel (or any .tsv editor) or Photoshop
(or any .png editor)."*

This is the no-code AI thesis stated in 2018 — four years before the term entered common parlance, and it dictated everything that followed: file-extension package formats (.gbai, .gbapp, .gblib, .gbkb, .gbdialog), a knowledge-base folder a user could edit by hand, and the insistence that a bot be a thing you own and open rather than a repo you clone.

The retrieval-first architecture is the important part. On day four, the knowledge base was built on Azure Search — an inverted index with semantic ranking, not a chat transcript. The .gbkb folder was always treated as a corpus to be indexed and retrieved from. When OpenAI finally published "RAG" as a technique in 2020, General Bots had already been running retrieve-then-generate for two years, with the index owned by the bot.

2019 — GENERAL BOTS BASIC: inventing a language for people who do not code

f78e06e6d · 2019-02-23 · "feat(basic): General Bots BASIC 2.0 with new keywords and parenthesis only when needed."

Version 1.3.0 (38fab9424, 2019-05-12) shipped GENERAL BOTS BASIC — a purpose-built, English-reading scripting language whose keywords are sentences a non-programmer already knows:

GET FROM customers WHERE status = "overdue"
IF COUNT(items) = 0 THEN
    TALK "All items well stocked!"
ELSE
    TALK "Low stock items: " + COUNT(items)
END IF
FOR EACH item IN items
    TALK "- " + item.name
NEXT

Today TALK, GET, SET, HEAR, CALL, FORMAT, CREATE FILE, ADD_SUGGESTION remain the surface language of the platform. 1,096 .bas files ship in the repository.

This was the deepest of the pioneering bets. While the industry was writing "no-code" as drag-and-drop canvas editors (which lock users into a vendor), General Bots shipped a textual, versionable, git-committable, AI-consumable programming language with an English-like surface syntax — the compromise most no-code platforms never made, and one that survives contact with an LLM because plain language is what LLMs read best.

2020 — Version 2.0: the packaging era

2.0.0 · 2020-07-12 · "chore(release): 2.0.0"

Four hundred commits, the first major version bump, and the consolidation of the package system: .gbapp units carrying their own syspackages, security.gbapp introduced (2020-07-26), and the bot lifecycle formalised — every .gbot found in a deploy folder deploys on startup. The CHANGELOG of this era is the moment the project stopped being a demo and became a product unit: installable, versioned, publishable.

2021 was the year of the unified agent identity. The same bot brain — same knowledge base, same BASIC scripts, same memory — was driven simultaneously from WhatsApp, LINE, Google Chat and Microsoft Teams. Every major assistant product of the following five years shipped as a channel adapter bolted onto a single model; General Bots had been building that seam since 2018.

The same year, BASIC grew into a scheduling and integration language: SET SCHEDULE (2021-08-09), SORT (2021-08-17), DATEADD/DATEDIFF (2021-08-15), new GET HTTP verbs (2021-11-20), and SEE CAPTION / SEE TEXT for computer vision (2021-11-16).

2022 — Charts, then ChatGPT in fifteen days

2022-06-03 — The CHART keyword: data visualisation, 18 months before Claude

DateCommitWhat landed
2022-06-03c799d9a2b"new(basic.gblib): CHART keyword dev started" — +4033 lines
2022-06-03d15834cd6"New CHART keyword.." — packages/basic.gblib/services/ChartServices.ts created
2022-07-06d15a1ffa1"CHART and IMAGE from GET HTTP calls" — charts from live API data

On 3 June 2022 a General Bots script could render a chart:

items = GET FROM sales WHERE month = "2026-05"
CHART items BY region AS COLUMN

That is 21 months before Claude 3 (March 2024) and 17 months before ChatGPT (November 2022). General Bots did not treat charting as an LLM feature — it was a deterministic keyword in a scripting language, the same category as TALK or GET FROM. Charting became an LLM capability only in 2024, by which point General Bots had two years of chart rendering to hand and simply wired the model into it (121766044, 2024-09-05, "CHART PROMPT and chart mode").

This is the pattern that repeats across the whole project: the capability comes first, the model arrives later and is absorbed as one more output format.

2022-12-15 — ChatGPT, fifteen days after launch

5424ca2e7 · 2022-12-15 · "new(all): ChatGPT integration."

ChatGPT launched to the public on 30 November 2022. General Bots shipped OpenAI support on 15 December 2022 — fifteen days later — as a first-class diff through the knowledge-base layer (packages/kb.gbapp/services/KBService.ts, AskDialog.ts), 1,532 lines in one commit.

The architectural decision matters more than the speed: ChatGPT was wired in behind the existing retrieval layer, not as a replacement for it. The .gbkb corpus, the chunker and the index stayed; the generator swapped. Provider-neutrality was inherited, not retrofitted.

Version 3.0 is the era where the model became a plugin. gpt.gblib sits beside whatsapp.gblib and llm.gblib in the same package hierarchy — a model provider is just another swappable module in a plugin architecture designed in 2018. This is why adding providers later took single-digit commits.

The ROUTER keyword (c2b2366fa) is the underrated one. Rather than hard-coding a single vendor, General Bots made model selection a first-class statement in a conversation script — the same way you pick a database driver. When Claude 3 arrived in March 2024, support landed three days later (b287e8877, 8 Nov 2024 was the provider's GA push to General Bots' pipeline). Today botllm carries nine provider adapters — Bedrock, Claude, Vertex, GLM, Kimi, Kiro, local llama.cpp — plus a council, a smart router and a rate limiter.

2025 — The Rust rewrite: leaving Azure, going sovereign

c88a24090 · 2025-10-06 · "Migration to Rust removal of Azure." (248 files, 68,826 deletions — the entire Node.js/TypeScript monolith removed in one commit)

This is the pivot of the modern era. The Node.js/TypeScript monolith — 43,761 insertions when it last moved (aee711fa3, 2022-11-18) — was replaced in a single decisive rewrite by a Rust workspace that could run entirely on its own infrastructure.

What that unlocked, all visible in the same year:

  • Sovereignty. No hyperscaler in the dependency graph. Vault, PostgreSQL, MinIO, Valkey,
    Qdrant and a local LLM replace Azure entirely.
  • Local models became first-class — llama.cpp support from 9e9db27bc (2025-10-14) and
    local fine-tuning experiments logged the same month (3f85f95af); today botllm/src/local.rs is a dedicated adapter alongside the hosted providers.
  • Offline capability — the platform now runs with no network egress to any AI vendor.
  • 2025-12-02 (9bc691e5d): the frontend split out into its own botui crate, and the
    next day (161b3c1d5) botbook — a book-length documentation set — was extracted from the repository.

The strategic claim this era makes: in an industry racing to rent its intelligence from American API providers, General Bets left the cloud entirely and shipped an AI platform you can own. Enterprise buyers in Brazil, Latin America and Europe cannot use OpenAI's API under GDPR or LGPD transfer rules. A self-hostable, MIT-licensed agent platform was not a feature — it was the market.

Two independent firsts landed here:

  • The Intent Compiler — natural language compiled into the platform's own language. When a
    user says "send an invoice to every client who is 30 days overdue", the LLM does not call a tool; it writes BASIC, which is then compiled, sandboxed, simulated by the safety layer, audited and executed. This is an agent that authors its own programs against a typed DSL — a design most agent frameworks never attempted because they lacked a language to target.
  • MCP client, weeks after the protocol's public release. Model Context Protocol was
    announced by Anthropic in November 2024; General Bots shipped a native client in December 2025 — as a first-party primitive of a bot language, not as a wrapper bolted onto a chat app.

Also in this window: agent reflection for self-improvement (14b2e6416, 2025-11-30), episodic memory, a code sandbox for Python/JS/Bash execution, SSE streaming, and LLM observability with cost tracking — all in one commit.

The 2026-05-07 decomposition is the engineering story of the project: 176K lines moved into standalone crates, botserver down from 312K to 205K lines, and a developer editing one feature went from an 8-minute rebuild to 2-3 seconds. That is what made everything after it possible.

Vibe Code: the platform that builds apps for the platform

e5baa15d9 and its successors (85e13be73, 773a1f124) give each project its own Incus VM with a real tool harness — file, run, git, logs, test. An agent inside General Bots can now provision an isolated Linux machine, write code, run it, commit it and read its own logs. botvibe also provisions a dedicated PostgreSQL database per project, per environment (bot_{name} for production, bot_{name}_dev for development) — dev work structurally cannot touch production data.

AI OS (a0cf52113)

Twelve additive migrations and eight new crates in one commit:

  • botagent — per-session Incus VMs, snapshots, sandboxed execution, per-org API keys
  • botautomation — natural-language schedules and a planner–executor–verifier engine
    with forks, auto-merge and an email/SMS delivery loop
  • botmemory — durable per-user/per-branch memory with recall injection and an
    extraction hook
  • botmarketplace — a .gbskill catalogue, seeded with 10 shareable skills
  • botconsent — a permission matrix, audit trail and HTMX consent cards
  • botconnectors — REST connectors with ACL snapshots and redaction
  • botbrowserpolicy — domain policy, budgets and browsing memory
  • botchannelbindings — default number/domain bindings with call logs

BotModels is General Bots' standalone Python vision/media service, reached over HTTP through BotModelsClient rather than being compiled into the Rust core. That split is deliberate: model servers get replaced on a different cycle than the platform, so they live behind an interface the host swaps out — the same reasoning behind the nine LLM provider adapters.

with its own history. Its 2025-11-29 commit is the **first occurrence of the string
botmodels anywhere in this repository's history** (git log -S'botmodels'), so any earlier

The through-line

Read the eight years as one argument, restated at each inflection point:

  • AI should be owned, not rented. 2018: bots as packages you open. 2025: a Rust platform
    with no hyperscaler in the dependency graph. 2026: MIT-licensed, runnable offline.
  • The interface should be language, not canvas. 2019: BASIC. 2025: an Intent Compiler that
    writes it. The LLM is a better front-end for a textual language than a drag-and-drop designer ever was — General Bets adopted that in 2019, seven years early.
  • Retrieval is the product; the model is a component. 2018: index the user's corpus. 2022:
    swap the generator, keep the index. 2026: nine providers behind one interface.

That third point is why this repository is still moving in 2026 while the frameworks that bet on a single vendor or a single canvas are being rewritten.

Epics

Six capabilities that shipped years before the industry treated them as a feature. Every one is verifiable in this repository, most of them from the founding commit.

Epic 1 — Talk to your documents (.gbkb), on day one

ce73db22f · 2018-04-21 · the initial commit

The first commit already contains deploy/kb.gbapp/dialogs/AskDialog.ts — a /answer dialog that resolves a natural-language query against the bot's knowledge base:

bot.dialog("/answer", [
  (session, args) => {
    let text = "";
    if (args && args.query)          text = args.query;
    else if (args && args.fromFaq)   text = /* FAQ lookup */;
    …

Backed by KBService (Azure Search, 4873e05ec, four days later) and the Azure Cognitive stack (AzureText). A user dropped a folder of documents into .gbkb and asked questions about them in plain language on day one of the project — four years before ChatGPT shipped, roughly six before Claude, and long before the word "RAG" entered a product description.

The folder stayed the interface: .gbkb was designed from the start to be opened, edited and committed, not uploaded into a vector store you cannot see. Documents remained .pdf, .md, .txt — the user's own files, on the user's own disk.

Epic 2 — The "projector": a rich-content surface with pluggable players

ce73db22f · 2018-04-21 · the initial commit

The chat surface in General Bots was never a message list. It was a projector — a rendering area beside the conversation, fed by a player registry. The initial commit ships five players:

PlayerRenders
GBImagePlayerPictures
GBVideoPlayerVideo
GBMarkdownPlayerRich text / formatting
GBBulletPlayerLists and structured answers
GBPowerBIPlayerEmbedded Power BI analytics

A bot answers in chat and simultaneously projects the artefact — a picture, a video, a formatted answer, or an embedded analytics dashboard — into the surface next to it. That is the "left chat, right content" pattern that Claude and every modern assistant adopted years later, already implemented as a pluggable player architecture in April 2018.

DateCommitWhat it added
2018-04-21ce73db22fFive players, including embedded Power BI
2018-05-16ae57d8b8c"Directline can now receive messages sent in projector-only fashion" — content rendered outside the conversation entirely
2020-02-036353dcea6Graceful degradation — "Content plain text to other channels when no projector is available"

The 2020-02-03 entry is the underrated one. A projector that renders rich content is only production-grade if it knows what to do on a channel that cannot display it — WhatsApp, LINE, SMS. General Bots solved that two years before rich content was common enough to need a fallback.

Epic 3 — A programming language for people who do not code

f78e06e6d · 2019-02-23 · GENERAL BOTS BASIC 2.0

English-reading syntax, git-committable, LLM-consumable. 1,096 .bas files ship today. The industry shipped drag-and-drop canvases; General Bots shipped text — and that decision is the reason an LLM could later drive the platform natively (see Epic 6).

Epic 4 — Charts as a language keyword

d15834cd6 · 2022-06-03 · ChartServices.ts created

A BASIC script renders a chart — 21 months before Claude 3, 17 before ChatGPT. Deterministic output format, not an LLM feature. The model was wired into the chart path two years later (121766044, 2024-09-05, "CHART PROMPT and chart mode"), inheriting a capability that already existed.

Epic 5 — One agent identity across every channel

2018-05-12 → 2021-09-30 · ca25d6bab (WhatsApp) · aaf2a38e4 (Google Chat) · d9f09425a (Teams)

The same knowledge base, the same BASIC scripts, the same memory, driven from WhatsApp, LINE, Google Chat and Microsoft Teams. Every major assistant since has shipped channel adapters; the seam was built here first and has been load-bearing for eight years.

Epic 6 — An agent that compiles intent into a real language

74f780daf · 2025-12-12 · Intent Compiler + MCP client + safety layer

A user says "invoice every client 30 days overdue". The LLM does not call a tool — it writes BASIC, which is compiled, sandboxed, simulated, audited and executed. Because the platform has a real language to target (Epic 3), the agent authors programs instead of filling in a JSON schema. This combination — no-code language first, agent compiler second — is the whole eight-year thesis in two commits.
