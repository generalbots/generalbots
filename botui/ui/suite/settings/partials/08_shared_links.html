Configuration

This tier is on by default: the local server listens on all interfaces. Open the network address from another device on the same network. If device-to-device traffic is blocked, allow inbound TCP port 8080 on this computer.

If the .local name does not resolve, use this computer's IPv4 address instead (for example http://192.168.1.20:8080).

How to configure

  1. Point a DNS record (for example files.example.com) at this computer's public address.
  2. Set the public base URL for this installation: 
    PUBLIC_BASE_URL=https://files.example.com
    or, in the product file: 
    public_base_url=https://files.example.com
  3. Restart the desktop app so new share links are composed against the domain; existing links keep their tokens.

The registrar token stays in the local vault and is never written to logs. Automatic DNS refresh and TLS certificates are part of the domain-provider work tracked in this issue; until that lands, keep the record updated at your registrar.

Not available yet. The desktop works offline, so this tier needs a free DNS zone and a relay for machines that cannot be reached directly. It ships disabled with the botpublic work tracked in #1864.

What it will do

The free account will hold a name — not your files. When a machine cannot be reached directly, the managed relay (relay.generalbots.org) keeps only an encrypted copy of the shared file and that copy expires. No manual relay configuration is required.

Master peer switch

Stop all P2P traffic for this installation. Offline mode keeps every connection on 127.0.0.1.

The relay endpoint is managed automatically. Changing this setting may require restarting the app to take full effect.
